# Support

OpenReady is a free, non-commercial open-source project maintained on a best-effort basis.

This document explains where to ask for help, what support the project can reasonably provide, and how maintainer capacity is protected.

## Support channels

Use the public repository when the information is safe to share:

- [GitHub Issues](https://github.com/Jpelotea/openready/issues) for reproducible bugs, accessibility barriers, documentation problems, and focused feature requests
- [GitHub Discussions](https://github.com/Jpelotea/openready/discussions) for questions, ideas, examples, and broader project conversation
- [SECURITY.md](SECURITY.md) for sensitive vulnerability reporting
- [ACCESSIBILITY.md](ACCESSIBILITY.md) for accessibility reporting guidance

Do not publish security exploit details, private personal information, account credentials, or confidential project data in an issue or discussion.

## What the project supports

Reasonable support includes:

- explaining how to run OpenReady locally
- clarifying checklist behavior
- reviewing reproducible software defects
- correcting inaccurate or confusing documentation
- evaluating accessibility barriers
- considering focused improvements that match the roadmap
- helping contributors understand validation and testing requirements

## What is outside scope

OpenReady does not provide:

- paid support, consulting, implementation, or hosting
- legal, security, accessibility, compliance, or certification advice
- guaranteed eligibility for Netlify or any other program
- emergency response for third-party repositories
- private customization work
- account recovery or cloud-data recovery, because OpenReady has no account system or backend
- guaranteed implementation of every feature request
- support for obsolete browsers or unmaintained private forks

OpenReady guidance is educational. Project maintainers remain responsible for evaluating their own legal, security, accessibility, governance, and operational needs.

## Response expectations

The maintainer aims to review new public issues regularly, but no fixed service-level agreement is offered.

As a practical target rather than a guarantee:

- clear routine reports may be acknowledged within seven days
- accessibility barriers that block a core task receive higher priority
- sensitive security reports follow the acknowledgement target in [SECURITY.md](SECURITY.md)
- feature requests may remain open until they fit a planned release or are closed as out of scope

Delays may occur because of maintainer availability, health, work, family responsibilities, or project priorities.

## Before opening an issue

Please:

1. Check the README and project documentation.
2. Search existing issues and discussions.
3. Use the most relevant issue form.
4. Describe one focused problem or proposal.
5. Include reproduction steps and environment details when reporting a bug.
6. Explain why the change supports OpenReady's users and community.

## Triage outcomes

A report may be:

- accepted for investigation
- converted into a smaller or more focused task
- linked to an existing issue
- deferred to a later roadmap
- closed because it cannot be reproduced
- closed as outside project scope
- redirected to a third-party project that controls the affected behavior

Closing or deferring a request is not a judgment about the reporter. It is a project-scope and capacity decision.

## Maintainer breaks and reduced activity

The maintainer may temporarily reduce reviews, pause releases, or limit new feature work. When practical, a public note should explain the pause and identify which channels remain monitored for security or serious accessibility reports.

No contributor is expected to remain constantly available. Rest, boundaries, and sustainable participation are part of project health.

## Community help

Community members may help by:

- confirming reproduction steps
- improving documentation
- testing fixes
- reviewing accessibility behavior
- answering questions with links to project documentation
- identifying duplicate issues
- proposing small, reviewable pull requests

Community replies must follow the [Code of Conduct](CODE_OF_CONDUCT.md) and must not impersonate maintainers or promise release dates.

## Non-commercial status

OpenReady does not offer paid support, premium access, sponsorship placement, advertising, affiliate promotion, or commercial services. Public support remains connected to the software and its open-source community.
